# Critique: briefing-grounded-signals (brief v1)

**Verdict: RESHAPE.** A grounded, deterministic, always-present non-AI summary is sound and cheap on privacy, but inc 1 duplicates a Home widget the brief never mentions, one signal is sourced wrongly, Q3 creates a pointless cloud data flow, and Phase A measures the wrong path with real data.

## Blocking objections
1. **Inc 1 duplicates Money Radar (shipped, not mentioned).** `ComputeMoneyRadarUseCase` is deterministic, added to Home on every compute [V `M/domain/usecase/dashboard/ComputeDashboardWidgetsUseCase.kt:348,1262`], default position 1 full width [V `DashboardWidgetRegistry.kt:44`]; already combines bills due, unresolved anomaly alerts and budget risk into localized "top reasons" [V `ComputeMoneyRadarUseCase.kt:174-203, 490-555`], with a neutral "finances healthy" line [V `:553`] and a navigating primary CTA [V `:87, 567-577`]. Home also shows FinancialWeather/upcoming [V `:1259`], PendingReviewAlert [V `:1351`], BudgetHealthWidget [V `:1369`] → 4 of 5 inc-1 signals already on screen, some twice. "On-device-only users get nothing" is overstated (they get the deterministic insight + Radar). Brief must: (a) state relation to Money Radar — reuse `MoneyRadarData` as digest source for bills/anomalies/budgets, or replace/merge; (b) justify a second summary of the same facts; (c) pick one "upcoming" source (Radar `getDueBills` vs `weather.upcomingItems`; domain Q3 omits Radar). Contradiction risk: Radar budget risk CRITICAL/HIGH/MEDIUM [V `:533-541`] vs brief CRITICAL/EXCEEDED.
2. **Signal 4 (unusual expense) not "already computed", not reliable as specified.** `AnomalyDetector` not in the Home pipeline (callers: `AnomalyAlertOrchestrator`, `InsightsEngine`, `SpendingPersonalityClassifier`) [V grep]; scoped to `monthPeriod`, not a "recent window" [V `AnomalyDetector.kt:175-200`]; `SingleCurrencyAnalyticsInput.from` throws if any row isn't in display currency [V `SingleCurrencyAnalyticsInput.kt:20-22`], `detect` catches → empty [V `AnomalyDetector.kt:183-190`] → mixed-currency users silently never see it; recomputing on every Home open bypasses orchestrator HIGH-only/cooldown/"looks normal" (brief's own Q4). Fix: read persisted unresolved alerts via `AnomalyAlertRepository.getActiveAlerts()` as Radar does [V `ComputeMoneyRadarUseCase.kt:260-275`].
3. **Q3 ("replace cloud briefing on Home") is a privacy regression and self-contradictory.** "Where" says template replaces only the deterministic fallback; Q3 says it replaces cloud text. If cloud generation keeps running (ai-fixes B3 "Cloud-route briefing generated/scheduled whenever briefing is on; Home card appears regardless" [V `docs/features/ai-fixes/brief.md:75`]) but Home no longer shows it, payload leaves the device; with notifications denied the user gets nothing visible → breaks fail-closed spirit + shipped-behaviour change. Fix: keep AI-ready precedence in the slot (today [V `M/ui/screens/home/HomeScreen.kt:530-540`]) or stop cloud generation along with display; first is minimal.
4. **Phase A not meaningful and touches real data.** Step 3 drives `GenerateTransactionInsightUseCase` (different prompt/input, borrows `DASHBOARD_BRIEFING` routing, hard 3000 ms timeout incl. cold Nano start [V `M/domain/ai/usecase/GenerateTransactionInsightUseCase.kt:52,63,87`]) → cold model false-fails; a pass says nothing about digest narration. ai-fixes B2a–B2d rewrite this path [V `workflows/active/ai-fixes-plan.md:25-28`] → result stale. "Save 5 manual expenses" writes real rows into the live ledger (shifts pace/budget/anomaly baselines, goes into backups), contradicting "synthetic data only". Fix: Phase A = device, Android/patch, AICore version, model status only, no expense writes; latency/grounding/Greek → Phase B harness after ai-fixes Part B.
