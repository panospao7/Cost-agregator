## Key Patterns

### 1. Sentinel-Value-as-Zero Anti-pattern (Issues #1, #2)
Both `RecurrenceFrequency.IRREGULAR.days = 0` and `ForecastHorizon.REST_OF_MONTH.days = 0` use zero as a sentinel meaning "not applicable" or "compute dynamically". Zero is a valid numeric value that easily slips through arithmetic undetected. **Recommendation:** Use nullable types (`Int?`) or sealed classes to force explicit handling.

### 2. Architecture Layer Violations (Issues #5, #6, #7)
Three domain model files import directly from `data.database.entity` or `data.repository`. The codebase shows awareness of this problem — `DomainDayBudgetStatus` and `DomainExpenseSummary` exist as proper domain alternatives to `BlockPartyDay`'s entity dependency. The migration appears incomplete.

### 3. Non-deterministic Defaults (Issues #3, #4, #19, #22)
Multiple classes use `System.currentTimeMillis()` or `UUID.randomUUID()` as default parameter values. This makes equality checks unpredictable, tests non-reproducible, and `copy()` semantics surprising (particularly issue #3 where `expiresAt` references `createdAt` in its default). **Recommendation:** Inject time/ID providers or use factory functions.

### 4. Missing Domain Invariants (Issues #9, #14, #15, #16, #18)
Data classes are used as pure value holders without `init {}` validation blocks. Negative amounts, NaN, inverted ranges, and mismatched list sizes can all be constructed. While Kotlin data classes are intentionally lightweight, financial domain models benefit from invariant enforcement to prevent subtle downstream bugs.

### 5. Inconsistent Numeric Types for Confidence/Percentage (Issues #12, #13)
Confidence scores alternate between `Float` and `Double` across models with no clear pattern. Percentages similarly mix types. This creates conversion noise and developer confusion. A.6 later addressed the mixed-type drift narrowly for `SpendingSummary`, `BudgetStatusSnapshot`, and `CategoryBreakdown`; `RecurringPattern.confidence` and other non-A.6 model families remain outside that epic's exact scope. **[ADDRESSED BY A.6 — scoped fields only]**

### 6. Duplicate/Ambiguous Class Names (Issues #8, #10)
`PeriodRange` exists in both `domain.model` (simple start/end) and `domain.analytics` (rich with period type and comparison). `SavingsGoal` and `GoalProtectionLevel` exist in both `domain.model` and `data.database.entity`. This forces developers to use fully-qualified names and creates import confusion.
