## Key Patterns
- Concurrency is the dominant correctness risk in this batch: assistant submission, AI runtime refresh, and period-based reports all rely on ad-hoc coroutines without strong request ownership.
- The split editor still lacks stable participant identity and full currency-aware presentation, and its apply path is not wired through to persistence.
- The spending-challenges feature is incomplete end-to-end: data loading, domain support, and UI rendering are all only partially implemented.
- Error handling and localization are uneven across screens, with several failures collapsing into “no data” states and multiple user-visible strings still hardcoded.
