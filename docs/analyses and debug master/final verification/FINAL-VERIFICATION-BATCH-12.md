## Key Patterns
- Relation-like IDs are repeatedly stored without FKs (`suggestedCategoryId`, `suggestedExpenseId`, correction/category IDs, `sourceArtifactId`, `splitTemplateId`).
- Multiple business rules exist only in UI/repository code and are not enforced at the persistence layer.
- Migration/backward-compatibility defaults are leaking into live behavior (`isSubscription = true`) instead of being confined to one-time backfills.
- Similar concepts are implemented differently across adjacent paths (calendar math, effective-amount aggregation, IRREGULAR recurrence handling), producing cross-feature drift.
