## Key Patterns
- Several DAO APIs assume uniqueness or single-row semantics that the schema does not actually enforce (`budgets`, `categories`, `return_windows`).
- Business-expense logic is inconsistent across list queries, aggregate queries, and downstream reporting code; ownership/share handling is not centralized.
- Legacy compatibility paths (`pending_reviews` name-only fallback, deprecated recurring DAO wiring) remain in production but are under-indexed or semantically incomplete.
- Time-based validity is inconsistently modeled: some reads use timestamps, others trust persisted status, and there is no universal expiry reconciliation step.
