## Key Patterns
- Several DAOs use `LIMIT 1` for lookups whose backing schema does not actually enforce uniqueness (`normalizedKey`, current-user member, linked group expense, and—missed in review—email source by `receiptId`).
- Convenience helpers hide important semantics: cross-DAO `@Transaction` wrappers, `REPLACE` inserts, and read-then-insert upserts all make the API look safer than it is.
- Merchant-location cache behavior is fragmented across DAO predicates, repository key generation, and correction storage; the global/area scoping model is not consistently encoded.
- Security-sensitive disconnect flows update status flags without fully revoking credential state.
