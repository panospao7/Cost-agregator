1	ReviewScreen.kt:304-325	🔴 Critical	State Bug / Memory Leak	processingIds is a mutableStateListOf that items are added to but never removed. Once a review is swiped, its ID stays in processingIds forever. If the user navigates away and returns (new composition), processingIds resets, but while in-session it grows unboundedly and blocks re-swipe of any previously processed item key if the list re-renders with the same IDs.	Add a LaunchedEffect that watches pendingReviews and prunes processingIds of IDs no longer present: LaunchedEffect(pendingReviews) { processingIds.removeAll { id -> pendingReviews.none { it.review.id == id } } }

A user can swipe-approve and tap the Reject button (or vice versa) before the item is removed from the list, causing a double-fire to the ViewModel.	Hoist processingIds into ReviewCard or disable the buttons when processingIds.contains(item.review.id). Alternatively, add debounce guards in the ViewModel.
