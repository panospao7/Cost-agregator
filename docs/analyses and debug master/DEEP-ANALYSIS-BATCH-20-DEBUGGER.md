## Key Patterns

### 1. Inconsistent Signature/Sorting Algorithms Across Components
The recommendation pipeline uses **two different** signature algorithms (field-level parsing vs. hashCode) and **two different** priority sorting approaches (raw ordinal vs. rank()). This breaks cross-batch deduplication and causes the wrong recommendations to be shown to users. This is the most impactful systemic issue.

### 2. Thread Safety Gaps in Shared Mutable State
Multiple instances of mutable state accessed from concurrent contexts without proper synchronization:
- `processedNotifications` (synchronizedMap with unsynchronized `removeIf`)
- `currentUserId` (plain var without @Volatile)
- `AtomicInteger` counter with non-atomic check-then-reset

### 3. Silent Error Swallowing
`RecommendationStateManager.dismiss()` and `clearForUser()` catch all exceptions with empty catch blocks. `DismissalHandler.dismiss()` logs but doesn't recover, leading to UI/DB state divergence. This makes production debugging nearly impossible.

### 4. Aggressive Restart Strategy
A 60-second repeating alarm to restart an already-running foreground service is excessive. Combined with the `requestRebind` in `onListenerDisconnected`, the service has multiple overlapping keep-alive mechanisms that drain battery unnecessarily.

### 5. Service Lifecycle Order
`onDestroy` cancels coroutines before stopping foreground, risking data loss for in-flight notification processing. The `super.onDestroy()` call at the very beginning may release listener bindings before the class's own cleanup completes.
