## Key Patterns
- **Period/temporal drift** is the biggest recurring theme: some components use custom `Calendar` math, others use `TimePeriodUtils`, and notification ML features depend on processing time rather than event time.
- **Metric inconsistency around `amount` vs `effectiveAmount`** is still present outside the core analytics path, especially in income/cash-flow logic.
- **Persistence of learned intelligence models is fragile**: one classifier keeps stale vocabulary after reload/retrain, and another can lose newly learned samples because writes are delayed and non-durable.
- **Investment reporting has multiple semantic mismatches** (fees ignored, 30-day stats labeled “all-time”, per-day portfolio values aggregated incorrectly), so portfolio insights are currently not trustworthy for decision support.
- **Test coverage is uneven**: there are focused tests for `FinancialHealthScoreV2`, `ConfidenceRouter`, `HybridExpenseClassifier`, and `MerchantNormalizer`, but there are no dedicated production tests for `FinancialHealthCalculator`, `RecurringIncomeTracker`, `CrossSourceDeduplication`, `TransactionClassifier`, `ExpenseCategoryClassifier`, `FeatureExtractor`, or `InvestmentTracker`. The existing `HybridExpenseClassifierStressTest` is also disconnected from production code and does not validate the real classifier implementation.
