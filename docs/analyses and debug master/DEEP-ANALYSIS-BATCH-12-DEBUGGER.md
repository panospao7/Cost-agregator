### Key Risks

1. **Crash risk (Issue #4)**: The `Category.init` block with `require()` is the most dangerous pattern. Any data corruption, migration bug, or raw SQL insert that violates the constraints will crash every query touching the categories table — potentially rendering the app unusable. This is a known anti-pattern with Room data classes.

2. **Data divergence (Issue #9, C1)**: The `imagePath` NOT NULL migration mismatch and warranty date calculation inconsistency create behavioral differences between user cohorts (fresh install vs. upgrade) and between code paths (auto-detected vs. manual), making bugs hard to reproduce.

3. **Financial accuracy (C2, C3, C4)**: The inconsistent use of `effectiveAmount` in business expense and warranty queries, combined with the locale-dependent dedupe key, can produce incorrect financial summaries and missed duplicates — directly impacting the app's core value proposition.
