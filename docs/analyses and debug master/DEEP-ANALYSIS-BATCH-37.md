## Key Patterns
- The available approved budget plan (`docs/plans/BATCH_20_BUDGET_FORECAST.md`) is still not fully realized: the rolling-window fix is not complete in `BudgetCalculator`, and zero-filled monthly history is still missing in both `BudgetForecastingEngine` and `BudgetAutopilotEngine`.
- Core budget semantics are fragmented: period windows, forecast lifecycles, and recommendation contracts are implemented in parallel in different classes instead of sharing one canonical model.
- Several APIs expose behavior they cannot truthfully support yet (`SharedBudgetManager.memberIds`, `getMemberContributions()`, `updateForecastAccuracy()`), which creates false confidence for callers.
- Data-model contracts like `Expense.effectiveAmount` and `transferDirection` are not applied consistently across analytics components, leading to materially wrong money calculations outside the main repository path.
