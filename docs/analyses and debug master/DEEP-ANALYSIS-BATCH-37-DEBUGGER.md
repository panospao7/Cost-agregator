## Key Patterns

### 1. **`effectiveAmount` vs `amount` Inconsistency (SYSTEMIC)**
The codebase has a well-documented `effectiveAmount` property on `Expense` that handles shared expenses and "not mine" flags. 3 of 11 files (`SharedBudgetManager`, `BusinessExpenseReportGenerator`, `CashFlowCalculator`) bypass this and use raw `amount`, producing inflated totals for shared expenses. Different parts of the app show different numbers for the same data.

### 2. **Duplicated but Divergent Analytics Logic**
`BudgetAutopilotEngine` and `BudgetForecastingEngine` independently implement trend detection, confidence scoring, historical data retrieval, and month-key generation with subtly different algorithms and timezone handling (UTC vs local). These produce contradictory results, confusing users who see conflicting signals across features.

### 3. **Flow Collection Anti-Pattern**
`CarbonFootprintCalculator` calls `.collect{}` on a Room Flow, which never terminates. This is a critical production hang. The correct pattern (`.first()`) is used correctly in other files in this batch.

### 4. **CancellationException Mishandling**
`BudgetMonitor` catches `Exception` broadly, which includes `CancellationException`. While it correctly classifies it as non-transient, it still swallows it instead of rethrowing, breaking structured concurrency guarantees.

### 5. **Hardcoded Period Assumptions**
Multiple components assume "month = 30 days" or "3 months = 90 days" instead of using calendar-accurate calculations. `SharedBudgetManager` always uses month boundaries regardless of the budget's actual period type.

### 6. **Incomplete Implementations Shipped as Functional APIs**
`SharedBudgetManager.getMemberContributions()` returns all-zero placeholder data. `BudgetForecastingEngine.updateForecastAccuracy()` is a complete no-op. These are exposed as public APIs without any indication they're non-functional.
