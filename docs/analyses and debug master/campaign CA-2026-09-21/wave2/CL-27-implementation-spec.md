## Work items
### WI-1 — Persist provider publication date (CA-E-01-001, P2, UNVERIFIED)
- Location: `M/data/repository/CurrencyRatesRepositoryImpl.kt` — `override suspend fun refresh(homeCurrency: String): Int` — 43–112, especially 69–80 and 104–106. Dependency: `M/domain/currency/CurrencyConverter.kt` — `suspend fun storeRates(rates: List<Triple<String, String, Double>>, source: String = "api", validDate: Long? = null)` — 552–574 **CURRENT HEAD cdf501d4**.
- Defect: refresh ignores the response date, so the existing store parameter defaults to download-day midnight instead of publication date.
- Change:
  1. **Actual response verified:** HTTP 200 from the production constant `https://www.ecb.europa.eu/stats/eurofxref/eurofxref-daily.xml` on 2026-09-25 at 18:04 +03:00 returned gesmes:Envelope → Cube → `Cube time='2026-09-25'` → child `Cube currency='USD' rate='1.1403'` and sibling rates. Publication field path: **`/gesmes:Envelope/ecb:Cube/ecb:Cube/@time`**. Rate fields: that dated node's child **`ecb:Cube/@currency` and `@rate`**. Namespaces: gesmes = `http://www.gesmes.org/xml/2002-08-01`; ecb = `http://www.ecb.int/vocabulary/2002-08-01/eurofxref`. Fixtures must represent that default namespace and nesting; no guessed JSON field.
  2. Parse the containing publication date before constructing/storing cross-rates. Strict ISO local-date parsing; encode its start of day in **UTC** epoch milliseconds, independent of locale/device timezone. Read rates only from the matching dated node. This daily endpoint needs one unambiguous publication; reject conflicting/multiple-date payloads rather than mixing a date from one node with rates from another.
  3. Pass `storeRates(..., source = "ecb", validDate = publicationMillis)` explicitly. Preserve fetch time for lastUpdated/setLastRateUpdate and cross-rate direction `toEur / fromEur`. Re-downloading the same publication retains its validDate/upserts the same pair/date.
  4. This provider supplies the field: **no download-time fallback is authorized**. Missing, blank, malformed or conflicting dates produce a typed local publication-unavailable failure with a controlled reason and no writes/freshness advancement. A narrowly scoped internal parser result/exception in this repository file is permitted (proposed, not an existing API); retain public `refresh(...): Int` and propagate failure, not a success-like count. If independent verification establishes a genuinely undated provider contract, stop for a human-approved typed fallback carrying an explicit unknown-date/untrusted-quality flag; never invent publication time.
  5. Retain secureDocumentBuilderFactory protections (114–127), privacy gate before network, IO dispatcher and finally/disconnect. A small internal parsing seam in the same file is allowed for deterministic fixtures; no HTTP-stack redesign/live-network tests. Leave converter manual-rate/default-date behavior unchanged.
- Acceptance criteria: publication D fetched D+1 has validDate D UTC and lastUpdated D+1, is available as of D but not before D, and never advances publication on repeat fetch. Invalid dates cannot mutate rates/settings.
