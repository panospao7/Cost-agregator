## Key Patterns

### 1. Regex `$` Literal vs. Anchor Confusion
Two files contain `$` in regex alternation groups intended to match literal dollar signs. Inside `[...]` character classes `$` is literal, but inside `(?:...|$|...)` alternation groups it's an end-of-string anchor. The fix is consistent: always escape as `\$` when matching a literal dollar sign.

### 2. Negative Modulo Bug (Systemic)
Multiple methods use `value % RANGE_SIZE` to map IDs into ranges, but Kotlin/Java `%` preserves the sign of the dividend. For negative values, this yields negative remainders, producing IDs outside the intended range. **All 6 methods** in `NotificationIdGenerator` share this bug. Use `Math.floorMod()` or `(x % n + n) % n` universally.

### 3. Integer Overflow with `Math.abs()`
`Math.abs(Int.MIN_VALUE)` returns `Int.MIN_VALUE` (negative). This is a classic Java pitfall that appears in `CsvExpenseImporter.generateColorForCategory()`. The pattern `Math.abs(x) % size` should always use bitwise masking instead: `(x and Int.MAX_VALUE) % size`.

### 4. Thread Safety Gaps
- `SimpleDateFormat` stored as a field and used across coroutines (CsvExpenseImporter)
- `ThreadLocal` caches for deprecated formatters that leak memory (DateFormatterUtils)
- Non-volatile reads of mutable state outside mutex (BKTree._size, root)
- The project is migrating to thread-safe `java.time` APIs but deprecated code paths remain

### 5. Missing Input Validation
Several utility functions accept unconstrained inputs and produce silently wrong results:
- `GeoUtils.haversineKm()` with invalid coordinates
- `AmountUtils.parseAmount()` with scientific notation-like strings
- `CsvExpenseImporter` with malformed CSV/dates
- `NotificationIdGenerator` with negative Long IDs

### 6. API Level Mismatch
`HapticFeedbackConstants.CONFIRM/REJECT` (API 30) used with `minSdk=26`. This will crash on ~40% of potential target devices (API 26-29). Android Lint should catch this but may be suppressed.

### 7. Database Instance Management Anti-Pattern
`CsvExpenseImporter` creates its own `AppDatabase` instances via a non-singleton extension function, bypassing Hilt DI entirely. This is inconsistent with the rest of the app and creates multiple database connections.
