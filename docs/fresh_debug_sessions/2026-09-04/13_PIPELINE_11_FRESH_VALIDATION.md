## 5. Universal candidates

1. **Sibling-file defect persistence** (same bug fixed in one file, missed in siblings): regex double-escape fixed in AmazonReceiptParser (d935ee5c), missed in UberReceiptParser (later fixed in 25c636e1), still present in AppleReceiptParser (NEW-P11-2026-001). The audit independently flagged the same pattern for Uber. This is a recurring pipeline pattern; U-PR fixes do not cover it because it is a verification-process gap, not a single code site. Recommend a repo-wide grep audit for `\\[sdw]` inside `"""` raw strings passed to `Pattern.compile`/`Regex`.
2. **Silent currency fallback** (universal category "mixed-currency money math / silent EUR fallback"): NEW-P11-2026-003 — parser-level hard-coded currency defaults with no quality flag. U-PR money fixes (MoneyAggregate etc.) do not reach parser output.
3. **Fail-open dedup on hash failure**: `sha256Prefix(...) ?: ""` (EmailReceiptIngestionService.kt:410) silently skips fingerprint dedup if hashing fails, while the messageId path fails closed (:199-200). Adjacent to the universal "fail-open privacy" category (privacy impact nil; correctness impact real). Not covered by an existing U-PR.
4. **CancellationException handling**: the P11 ingestion service is CLEAN (all catches rethrow) — evidence that the U-PR1 pattern is applied here; no action needed.
