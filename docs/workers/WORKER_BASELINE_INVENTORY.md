## Workers by Category

### Registered Workers (in `WorkerRegistry.entries` + `WorkerSpec.DEFAULTS`)

These 7 workers are part of the canonical schedule-and-pause lifecycle:

1. **`location_backfill`** — `LocationBackfillWorker`
2. **`merchant_key_backfill`** — `MerchantKeyBackfillWorker`
3. **`warranty_expiration_check`** — `WarrantyExpirationWorker`
4. **`data_retention`** — `DataRetentionWorker`
5. **`bill_reminder_periodic`** — `BillReminderWorker`
6. **`receipt_matching`** — `ReceiptMatchingWorker`
7. **`ai_daily_briefing`** — `DailyBriefingWorker`

### Dynamically Scheduled Workers (not in registry)

8. **`NotificationIntakeWorker`** — Scheduled per-notification by `NotificationIntakeCoordinator` and `NotificationIntakeRecoveryScheduler`. Uses unique work names so each intake runs independently. Deliberately excluded from `WorkerRegistry` because it has no fixed schedule — each notification creates a new work item.

### Non-WorkManager Workers

9. **`SourceLinkBackfillWorker`** — A `@Singleton` class (not a `CoroutineWorker`). Invoked directly by `SourceLinkBackfillViewModel`. Uses `writeBarrier.checkWritesAllowed` as a minimal guard. Not a WorkManager worker, so it is correctly excluded from `WorkerRegistry`.

### BroadcastReceivers (not WorkManager)

10. **`BootReceiver`** — Starts `NotificationCaptureService` on boot/package-replace. No guard.
11. **`ServiceRestartReceiver`** — Restarts `NotificationCaptureService` on alarm. No guard.
12. **`DismissReminderReceiver`** — Dismisses a bill reminder delivery. No guard; uses injected `RecurringLifecycleCoordinator`.
13. **`SnoozeReminderReceiver`** — Snoozes a bill reminder delivery. No guard; uses injected `RecurringLifecycleCoordinator`.
