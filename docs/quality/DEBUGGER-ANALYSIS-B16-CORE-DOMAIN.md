### Key Patterns

1. **False coverage (Critical):** `RecurringExpenseEngineStressTest.kt` tests locally-defined functions, not the production engine. 591 lines of tests that validate nothing about real code.
2. **Timezone non-determinism (Systemic):** `FakeTimeProvider`, `SynthesisEngineGoldenTest.atTime()`, `SynthesisEngineTest.millis()`, and `TimePeriodUtilsStressTest` all use system-default timezone. Tests may pass in UTC but fail in UTC+5:30.
3. **Wall-clock coupling:** 4 test files use `System.currentTimeMillis()` for test data, making results non-reproducible.
4. **Disabled critical tests:** 5 `@Ignore`d tests hide real production bugs (money arithmetic, notification ID overflow) while CI reports green.
5. **Bug-asserting tests:** Tests in `SplitCalculatorStressTest` and `MerchantCleanerStressTest` assert **incorrect** (buggy) production behavior — they will break when bugs are fixed.
6. **Global state mutation:** `TimeZone.setDefault()` and `Locale.setDefault()` mutations are unsafe for parallel test execution.

## Verdict

**FAIL**

Two critical issues disqualify this batch:

1. **`RecurringExpenseEngineStressTest.kt` provides zero real coverage** — it tests locally-defined mock functions, not the production `RecurringExpenseEngine`. This is the most severe type of test bug: tests that pass and report coverage but validate nothing.
2. **Tautological assertions** (`assertTrue(x != null || x == null)`) that always pass regardless of the system under test.

Additionally, the systemic timezone dependency via `FakeTimeProvider.forDate()` affects multiple test files and could cause widespread failures on non-UTC CI runners. The 5 `@Ignore`d tests covering financial correctness and ID generation boundaries represent real production risk that is currently unvalidated.

**Minimum actions required before PASS:**
- Rewrite `RecurringExpenseEngineStressTest` to test the real production engine
- Fix tautological assertions to test meaningful conditions  
- Fix `FakeTimeProvider.forDate()` to use UTC (single fix, broad impact)
- Re-enable or fix the 5 `@Ignore`d tests in `MoneyTest` and `NotificationIdGeneratorTest`
